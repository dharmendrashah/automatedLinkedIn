# Project memory

Living notes for people and AI agents working on automatedLinkedIn. Read this before starting a task. When a task is done, update it (see "How to maintain this file"). Keep it short, factual, and current.

## How to maintain this file

- Add a decision, gotcha, or open item only if it would save the next person time. Do not log routine changes; git history does that.
- Edit or delete entries that are no longer true. Do not leave stale facts.
- One line per entry where possible; put the date on decisions and the changelog.
- Never store secrets, tokens, passwords, or the git remote URL here.

## Gotchas

- `tsx`'s dynamic-`import()` loader mishandles Camoufox's optional `maxmind` dependency (used for `geoip: true` with a proxy): `(await import('maxmind')).default.Reader` resolves to a real function under plain `node`, but to `undefined` under `tsx`, for this package's TypeScript-compiled, getter-based CJS export shape (confirmed 2026-10-15 with a side-by-side repro: identical `createRequire`-based resolution, only the loader differed). Crashes with `maxmind.Reader is not a constructor` right at Camoufox launch. Affects any geoip-using Camoufox launch run through `tsx`, including `pnpm --filter @automatedLinkedIn/spider dev:worker` with a real proxy locally — not yet fixed there. The devtools recorder (`dev:record`) works around it by building and running compiled JS with plain `node` instead of `tsx`.
- Kustomize's `secretGenerator`/`configMapGenerator` `envs:` (reading `deploy/overlays/*/secrets.env` and `config.env`) does **not** strip quotes from `KEY="value"` lines — unlike Docker Compose's `env_file` and Node's `dotenv`, which both do. A value copied from the root `.env`-style files with its quotes kept gets deployed with the literal `"` characters baked in, indistinguishable from a wrong value (e.g. `IPINFO_TOKEN` looked like an invalid/revoked ipinfo token on staging on 2026-10-14, confirmed by `kubectl exec ... -- od -c` on the pod's env var: 16 bytes instead of 14, quotes included). Fix: no quotes in any `deploy/overlays/*/secrets.env` or `config.env` value, ever (the committed `*.example.env` files already show this correctly). If a staging-only value looks wrong, check the real deployed byte count (`kubectl exec <pod> -- sh -c 'printf "%s" "$VAR" | wc -c'`) before assuming the value itself (e.g. a token) is bad.
- `secrets.env`/`config.env` are git-ignored; only the GitHub Actions secret `STAGING_SECRETS_ENV`/`STAGING_CONFIG_ENV` is what `staging.yml` actually deploys (`gh secret set STAGING_SECRETS_ENV < deploy/overlays/staging/secrets.env`). Editing the local file alone changes nothing on staging until that secret is updated and `gh workflow run staging.yml --ref main` runs.
- Run `vitest` through the package scripts (`pnpm test:unit:run`); calling it directly in `apps/brain` also picks up the compiled tests in `dist/` and fails them. Integration tests need `.env.test` or `NODE_ENV=test DATABASE_URL=...` in the shell. Repo rule: every lint warning is fixed, including old ones (the spider and brain `object-curly-newline` warnings were cleared on 2026-10-14).
- zsh-autoenv prompts to authorize the root `.env` in every new agent terminal and swallows the first command typed (it is taken as the answer); send the command a second time, or `export AUTOENV_ASSUME_YES=1` first. The root `.env` is read by docker compose only; `pnpm dev` for brain reads `apps/brain/.env`, so `ABUSEIPDB_API_KEY` must be in the one that matches how brain runs.
- `pnpm lint:fix` can rewrite files you did not touch (`object-curly-newline`); that is now wanted, since all warnings must be fixed. Run it per package, check `git status`, and keep only sensible changes.
- Signed links need a service account: `Storage.getSignedUrl` fails with `Cannot sign data without client_email` on `gcloud auth application-default login` user credentials (checked on this machine). Locally use `gcloud auth application-default login --impersonate-service-account=<sa>` (the user needs `roles/iam.serviceAccountTokenCreator` on it); still not set up for local dev. On GKE staging this is now wired (2026-10-15, `deploy/gcp-setup.md` "Session recordings"): GSA `brain-recording-links@automate-linkedin-511215.iam.gserviceaccount.com` (read-only on `runs/` and `recordings/`, `serviceAccountTokenCreator` on itself, Workload Identity bound to `automatedlinkedin/brain`), annotated on `deploy/base/brain.serviceaccount.yaml`. Without the annotation the error is not a permission error but `Invalid form of account ID <project>.svc.id.goog` from the IAM Credentials API (the pod has no real Google identity to sign as, only the raw Workload Identity pool string).
- Video in a recording: Camoufox 0.5.8 with `playwright-core` 1.62 records a playable VP8 webm (800x600, about 31 kb/s) with `recordVideo`, but only if Playwright's ffmpeg is installed (`pnpm --filter @automatedLinkedIn/spider exec playwright-core install ffmpeg`, revision 1011 into `~/Library/Caches/ms-playwright`). The worker Dockerfile now runs that (the image builds; verified 2026-10-12, with Camoufox and ffmpeg in `/home/node/.cache`). The video file is complete only after `context.close()`, so the recorder finishes after the browser closes.
- `pnpm --filter <app> exec vitest <path fragment>` also matches the compiled tests in `dist/` and then fails with `Vitest cannot be imported in a CommonJS module`. Pass the full `src/.../x.unit.test.ts` path, or use the package's `test:unit:run`.
- `replace_string_in_file` takes old text first and new text second: swapping them silently duplicates code (it happened twice this session). Check the result after a big replacement, and use `\n` only inside JSON tool strings, never in a plain one.
- RabbitMQ 4.3 quorum queues redeliver `nack(requeue=true)` instantly and do NOT count it toward `x-delivery-limit`, so a failing consumer spins (about 100 attempts a second). Spider retries by publishing a copy with an `x-retries` header after a back-off and dead-letters after 3 retries; never use nack-requeue as a retry loop.
- Application Default Credentials are per machine and may belong to a different Google account than `gcloud`'s active one (here ADC was another organisation's account), so a worker can reach GCS and still get `storage.objects.create denied`. Check with `gcloud auth application-default print-access-token` or the error text. To keep other work untouched, log in to a separate ADC file: `CLOUDSDK_CONFIG=$HOME/.config/gcloud-spider gcloud auth application-default login`, then point `GOOGLE_APPLICATION_CREDENTIALS` (local) or `SPIDER_GCP_CREDENTIALS` (compose) at `$HOME/.config/gcloud-spider/application_default_credentials.json`.
- `camoufox@0.5.8` has the peer `playwright-core` `<1.63`, so spider pins `camoufox` and `playwright-core@1.62.0` exactly and must not use the 1.64 Playwright image (the worker image is now `node:25-bookworm-slim` plus Firefox libraries and `camoufox fetch`). `camoufox` is ESM-only but `require('camoufox')` works on Node 25. The browser build is 1.29 GB (about 2.5 GB unpacked) in `~/Library/Caches/camoufox` (macOS) or `~/.cache/camoufox`; `pnpm --filter @automatedLinkedIn/spider exec camoufox fetch` takes about 15 minutes and prints no progress without a TTY. Real-browser tests need it and take about 2.5 minutes: `pnpm --filter @automatedLinkedIn/spider exec vitest camoufoxDriver.e2e.test.ts --run --testTimeout=120000`.
- In this Cursor/VS Code agent shell, `pnpm exec <bin>` run from the repo root does not find package binaries; use `pnpm --filter @automatedLinkedIn/spider exec ...` (or `cd` into the package).

- Kubernetes: `app-secrets` is generated with a content hash in its name, so changing `STAGING_SECRETS_ENV` creates a new Secret and rolls every workload. A StatefulSet pod that is stuck (for example `CreateContainerConfigError` from a missing secret key) is NOT replaced by the rollout, because a StatefulSet waits for the old pod to become Ready. After fixing the secret, delete the stuck pod (`kubectl -n automatedlinkedin delete pod rabbitmq-0`); its PVC is kept. Seen on 2026-10-11 when staging was deployed before `LINKEDIN_CRED_ENC_KEY` and the RabbitMQ keys were in the secret: brain crash-looped on the missing key and `rabbitmq-0` stayed stuck.
- Every new required production env var (no `devDefault`) must be added to `STAGING_SECRETS_ENV` (or `STAGING_CONFIG_ENV`) before the PR that needs it is merged, because merging to `main` deploys staging immediately. Set it with `gh secret set STAGING_SECRETS_ENV < deploy/overlays/staging/secrets.env` after adding the key to the local git-ignored file. `STAGING_SECRETS_ENV` now holds `LINKEDIN_CRED_ENC_KEY`, `RABBITMQ_DEFAULT_USER` and `RABBITMQ_DEFAULT_PASS`.

- A brain unit test that imports the real `trpc` (for `router`/`userProcedure`) pulls in `trpc.ts` → `./api/identity` (a value import) → `auth` → `env`, so envalid runs `cleanEnv` and calls `process.exit(1)` if `DATABASE_URL` is missing (there is no committed `.env.test`). Such tests must `vi.mock('env', ...)` with a full env object (see `router.unit.test.ts` and `linkedInAccount.unit.test.ts`). Tests that mock `./identity` (like `me`) avoid loading `env` entirely because trpc.ts imports `Context` as a type only.
- brain is CommonJS (`module: commonjs`), so top-level `await import(...)` is a TS1378 error. Use static imports in tests; `vi.mock` is hoisted above them anyway. A class referenced inside a `vi.mock` factory must be declared inside `vi.hoisted` (not a plain top-level `class`), or it hits the temporal dead zone.
